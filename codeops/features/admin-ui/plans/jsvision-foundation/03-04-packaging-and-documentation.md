# Packaging and Documentation: JSVision Admin Foundation

> **Document**: 03-04-packaging-and-documentation.md
> **Parent**: [Index](00-index.md)

## Overview

This component makes the embedded TUI reproducible in source and packed CLI installations and separates public consumer guidance from the test-only playground instructions. It also owns repository-level contract checks that prevent the retired GUI loader or reserved CI namespace from re-entering public surfaces. (AR-3, AR-4, AR-22, AR-24, AR-25)

## Dependency and Package Contract

`@jsvision/core` and `@jsvision/ui` are direct production dependencies of `@portaidentity/cli` at the same compatible release. `fs-ext-extra-prebuilt@2.2.13` is the sole additional runtime utility and is wrapped by one narrow kernel-lock adapter. No optional peer, runtime dynamic discovery, extra JSVision package, custom lock framework, or new workspace is introduced. The root lockfile is generated by Yarn Classic. Porta's existing Node 24 LTS development workflow, frozen install, `yarn deps:check`, production dependency audit, lockfile/integrity review, focused adapter tests, and packed CLI smoke prove the dependency and package contract. No separate platform/runtime matrix or CI workflow is added. (AR-4, AR-22, AR-35, AR-47)

The built CLI archive must contain all compiled `src/admin/` modules through the existing `dist` package rule, launch `porta admin` from an isolated temporary installation, and contain no reference to `@portaidentity/admin-gui`. The smoke uses a PTY or a deterministic preflight path; it must not require source-workspace resolution. (AR-3, AR-19, AR-25)

Because SDK auth hooks are public contract changes, the SDK build, type declarations, type-compatibility tests, packed consumer, and clean-revision assurance selector are required. SDK and CLI versions remain release-tool-owned and are not hand-edited by this plan. (AR-17, AR-25)

## Public Documentation

Update the CLI package README and public VitePress CLI documentation to:

- list `porta admin` and remove `porta gui`;
- state the interactive TTY requirement and incompatible automation modes;
- show generic operator-owned HTTPS `--server` examples;
- describe browser/manual authentication, reauthentication, verified session summary, explicit cross-server replacement confirmation, and `--insecure` warning at consumer altitude;
- describe this milestone honestly as an administration shell foundation, without promising unimplemented modules.

Public content must not contain `ci.portaidentity.com`, the playground email/password workflow, local ports, generated-secret paths, mkcert mechanics, Compose project/volume names, or maintainer reset procedures. (AR-2, AR-18, AR-24)

## Maintainer Technical Documentation

Add one focused guide under `techdocs/` and link it from the appropriate unpublished development/infrastructure index. It owns exact prerequisites, hostname, port overrides, mkcert trust, lifecycle commands, first-run bootstrap, MailHog URL/use, persistence, reset confirmation/effects, stale credential recovery, troubleshooting, and explicit non-production restrictions. It must repeat the IPv4-only loopback/test-cookie cautions from project guidance and explain that test DNS is not a trust boundary. (AR-5, AR-9–AR-15, AR-23, AR-24)

## Repository Contracts

Fast structure specifications should assert:

- CLI manifest owns exactly the approved JSVision runtime packages in lockstep;
- `src/commands/gui.ts`, GUI registration, and retired package references are absent;
- server initialization output names `porta admin`, and refreshed project guidance no longer describes `porta gui` as retained;
- `porta admin` registration and expected `src/admin/` boundaries exist;
- root `admin:env` command and `docker/admin-playground/` ownership are present;
- generated runtime paths are ignored;
- the reserved CI hostname occurs only in test/technical/playground scopes, never public docs or package README;
- no generated certificate, private key, secret environment file, or build output is tracked.

These contracts protect package/document boundaries; behavioral expectations remain owned by [Testing Strategy](07-testing-strategy.md). (AR-3, AR-13, AR-22, AR-24)

## Error Handling

| Error case                                                       | Handling strategy                                                                            | AR ref              |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------- |
| JSVision versions differ or resolve incompatibly                 | Frozen install/structure contract fails; do not add compatibility shims                      | AR-4, AR-22         |
| Packed CLI cannot load admin modules                             | Package smoke fails completion                                                               | AR-25               |
| Public docs expose test namespace or maintainer secrets workflow | Structure/doc boundary test fails                                                            | AR-24, AR-26        |
| SDK declaration/consumer breaks                                  | Type compatibility or clean-revision compatibility gate fails; preserve default API behavior | AR-17, AR-25        |
| Generated runtime/certificate/secret becomes tracked             | Structure and Git-content checks fail                                                        | AR-11, AR-13, AR-25 |

## Testing Requirements

- Repository structure specifications before manifest/command/doc implementation.
- Frozen install, dependency check, build/typecheck/lint, and package-content inspection.
- Isolated packed CLI launch, focused native-lock adapter tests in Porta's existing workflow, and SDK TypeScript consumer tests.
- Public VitePress build plus literal scope scans for the reserved namespace and retired GUI.
- Final full and specialized gates from [Testing Strategy](07-testing-strategy.md).
