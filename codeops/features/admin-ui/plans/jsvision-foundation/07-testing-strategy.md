## Testing Overview

The immutable oracle is split by security/public contract, terminal application behavior, and playground lifecycle. Specification tests are written from the rows below before their corresponding implementation. Implementation tests follow green and may cover internal mechanics.

### Coverage Gate

| Measured source                                                                                                                                                                                                                           | Minimum line coverage |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------: |
| `packages/cli/src/auth/**/*.ts`, `packages/cli/src/credential-store.ts`, `packages/cli/src/credential-lock.ts`, `packages/cli/src/admin/session-service.ts`, `packages/sdk/src/auth/cli-auth.ts`, `docker/admin-playground/scripts/*.mjs` |                   90% |
| `packages/cli/src/admin/state.ts`, `packages/cli/src/admin/application.ts`, `packages/cli/src/global-options.ts`, `packages/cli/src/client-factory.ts`, `packages/sdk/src/transport/node-transport.ts`                                    |                   80% |
| `packages/cli/src/admin/presentation.ts`, `packages/cli/src/commands/admin.ts`                                                                                                                                                            |                   60% |

Coverage is measured only for these exact globs. CLI/SDK Vitest configurations enforce their per-glob line thresholds. Playground scripts use Node's built-in test coverage with `--test-coverage-include=docker/admin-playground/scripts/*.mjs` and `--test-coverage-lines=90`; no new coverage framework is introduced. Type-only files, barrels, generated output, process entry points, direct child-process/filesystem adapters, platform-inapplicable native branches, Compose/YAML, nginx configuration, documentation, and packed artifacts are excluded. Each adapter exclusion is limited to one function or branch and remains verified by specification, native-adapter, PTY, configuration, structure, and live integration gates. (AR-41)

Test names use `should [expected behavior] when [condition]`. Real JSVision application/render/event objects, temporary files, local HTTP/JWKS servers, PTYs, Docker services, and packed consumers are preferred; mocks are limited to browser opening, remote identity endpoints, filesystem failure injection, DNS answers, and clocks/process ownership where those are the true boundary. (AR-19, AR-25)

## Test Data and Isolation

- Generate an ephemeral P-256 issuer key/JWKS and signed tokens with explicit claims; never use committed private keys.
- Use temporary credential directories with owner-only permissions and controlled contention/process-exit boundaries for kernel-lock tests.
- Use real JSVision headless application/render/event objects; browser opening and remote endpoints are the only mocked edges.
- Live playground tests use the fixed Compose identity inside a disposable isolated Docker context/daemon, apply port overrides, verify resolver preflight, and clean only exact owned resources. No public project-name override exists.
- Mail assertions inspect MailHog's test API/UI boundary without recording passwords, tokens, or full message artifacts in durable logs.
