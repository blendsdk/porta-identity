## Resolution Notes

**AR-48 through AR-52:** Imported as resolved from the user's explicit acceptance of the proposed
menu, terminology, identity dialog, session-memory context, creation behavior, and bounded fields.

**AR-55:** The user explicitly chose to request and display all organizations at once. The CLI may
traverse the server's bounded API pages internally, but this transport detail is not exposed in the
interface.

**AR-53, AR-54, and AR-56 through AR-58:** The user explicitly accepted the recommendations as a
batch.

**AR-59:** The existing OIDC account builder includes `roles` and `permissions` in UserInfo. The
admin UI currently validates only `sub`, `name`, and `email`; it will validate the existing RBAC
arrays into ephemeral application capability state instead of adding a redundant endpoint. The
claims are advisory presentation data, are not persisted, and never replace server authorization or
`403` handling. Existing legacy `porta-admin` compatibility remains effective.

**AR-60 through AR-68:** The user approved complete core user management and explicitly rejected
special multi-administrator locking, external tenant-deletion polling, and similar rare-race
machinery. SDK contract corrections are in scope. The UI follows a familiar Users list and user
detail flow while later roadmap features continue to own roles, sessions, 2FA, global audit, and
bulk operations.

**AR-69 and AR-70:** The purge uses a direct explicit confirmation without type-to-confirm ceremony.
All import/export functionality, including per-user export, is owned by RD-09 instead of RD-03.

The user reviewed and approved RD-03 on 2026-08-29 with all AR-60 through AR-70 decisions intact.

The user reviewed and approved RD-02 on 2026-08-28 with all AR-48 through AR-59 decisions intact.
