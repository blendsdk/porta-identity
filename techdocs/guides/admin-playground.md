# Admin Playground

The admin playground is a maintainer-only, non-production environment for exercising the embedded
`porta admin` shell against the current Porta source tree. It uses one fixed Compose project with
PostgreSQL, Redis, Porta, nginx, and MailHog. It is part of the existing repository workflow; it is
not another workspace, application, or CI workflow.

## Prerequisites

- Node.js 24 LTS and Yarn Classic 1.x
- Docker with the Compose plugin
- `curl`
- `mkcert`, with its local CA installed by running `mkcert -install`
- The fixed hostname `porta-admin-playground.ci.portaidentity.com` resolving to exactly the IPv4
  loopback address `127.0.0.1`, with no AAAA response
- Free loopback ports `3543` for HTTPS and `8026` for the MailHog web UI

The lifecycle preflight checks these requirements before Docker mutation. Override the two public
ports only when needed:

```bash
PORTA_ADMIN_HTTPS_PORT=4543 PORTA_ADMIN_MAILHOG_PORT=9026 yarn admin:env up
```

## Start and Use the Playground

Run the lifecycle command from the repository root:

```bash
yarn admin:env up
```

The first start builds the existing Porta image, runs migrations, and invokes `porta init`. Enter a
new administrator password at the hidden prompt. The fixed non-secret bootstrap identity is
`Playground Administrator <admin@playground.porta.test>` in the `porta-admin` organization. The
password is sent only to the interactive initialization process and is not written to the
playground runtime files.

Open the administration shell after startup:

```bash
porta admin --server https://porta-admin-playground.ci.portaidentity.com:3543
```

The admin UI first opens a blocking `Authentication required` dialog. Activate `Authenticate` with
Enter or the mouse to start the browser flow; `Quit` is the only alternative. Cancelling or failing
authentication returns to this dialog.

After browser authentication, the organization chooser opens automatically. Select `Porta Admin`
and activate Switch to enter that context, or use Create to enter a name, optional slug, and optional
default locale; a successful create selects the new organization. The Organizations menu can reopen
the chooser at any time. Press `F10` to open the hamburger menu containing `Who am I…`,
`Reauthenticate`, and `Quit`.
Organization selection is process-local context and does not issue another token.

With an organization selected, use the Users menu to browse or create a user. Enter on a user row
opens the detail workspace. The menu and detail actions remain permission-sensitive.

Applications is deployment-global and can be opened before selecting an organization. Use it to
create an application and manage its modules. OIDC Clients is organization-scoped: select an
organization, open the client DataGrid, then use the detail actions to edit configuration or manage
secret metadata. Newly generated secret plaintext is shown once and is not retained after the
dialog closes. Switching organizations clears the client workspace.

Mail generated by Porta is captured internally by MailHog. View the inbox at
`http://127.0.0.1:8026`. SMTP is not published on the host.

## Lifecycle and Persistence

Inspect or stop the fixed playground without deleting its data:

```bash
yarn admin:env status
yarn admin:env stop
```

PostgreSQL and Redis use the exact `porta-admin-playground_postgres_data` and
`porta-admin-playground_redis_data` volumes. Infrastructure secrets remain stable in the ignored,
owner-only `docker/admin-playground/runtime/secrets.env` file. TLS material remains in the ignored
runtime directory. A later `yarn admin:env up` reuses this state and does not ask for another
administrator password.

Lifecycle mutations use a bounded kernel lock. If another `up`, `stop`, or `reset` owns it, the
competing command fails instead of running concurrently.

## Reset

Reset is intentionally destructive only for the two owned PostgreSQL and Redis volumes:

```bash
yarn admin:env reset
```

Type the exact confirmation phrase `reset porta-admin-playground`. The command requires an
interactive terminal even with `--yes`, because the replacement administrator password must use a
hidden prompt. Before deletion, reset repeats the full prerequisite check. It then stops the fixed
project, removes the exact owned volumes, proves both are absent, rotates infrastructure secrets,
and bootstraps a clean environment. It preserves the mkcert CA, generated exact-host TLS material,
and CLI credentials outside the playground.

Existing CLI credentials become stale after reset because the server keys and admin client are
recreated. Clear them with `porta logout`, then start `porta admin` again to complete a fresh OIDC
login.

## Troubleshooting

- **DNS preflight fails:** confirm the hostname has exactly one A response, `127.0.0.1`, and no
  AAAA response. Do not substitute a production hostname.
- **Certificate preflight fails:** run `mkcert -install`, then retry. The retained certificate must
  match the hostname, its private key, its validity window, and the current mkcert root.
- **A port is unavailable:** stop the process using the reported loopback port or choose valid,
  distinct unprivileged overrides. Partial recovery accepts an occupied port only when the exact
  running playground service owns it.
- **Status is `partial`:** rerun `yarn admin:env up`; the command resumes the fixed project under the
  lifecycle lock.
- **Reset reports a remaining volume:** correct Docker daemon, context, or permission problems and
  rerun reset. Secrets are not rotated until absence is proved.
- **No email appears:** check `yarn admin:env status`, then open the loopback MailHog URL. Reset and
  stop/start replace the disposable MailHog container; they do not publish SMTP.

## Packed Admin Journey

After `yarn admin:env up`, run the packed CLI journey with Node.js 24 LTS:

```bash
PORTA_ADMIN_PLAYGROUND_PASSWORD='<playground-password>' \
  node --test docker/admin-playground/tests/admin-cli.e2e.spec.test.mjs
```

The password is read from the environment and must not be committed. `yarn admin:env up` rebuilds
the current Porta image, and CLI verification builds the `dist` tree packaged by this test. The
journey creates a high-entropy organization, user, global application, module, organization client,
and client secret; verifies their UI behavior; cleans only nonce-owned resources; and confirms
terminal restoration.

## Security Boundary

This environment is not for production, demonstrations with real identities, or persistent
credentials. The public `*.ci.portaidentity.com` wildcard points each client back to its own IPv4
loopback; it exposes no remote Porta service and is not a trust boundary. Keep playground cookies
host-only and never set `Domain=.ci.portaidentity.com`.

Subdomains below `ci.portaidentity.com` are different origins but the same browser site. Use
different registrable domains for tests that require cross-site behavior. Do not add or depend on an
AAAA record unless every local service intentionally binds IPv6 loopback.
